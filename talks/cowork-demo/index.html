Customer Intelligence Agent

Challenge

As a solution architect, I need to quickly help my sales colleague prepare for a customer meeting. I am not a vertical specialist, so I need to prepare for meetings in depth.

Solution

I shift-left GenAI and build a reusable plugin that my colleagues and I can use. I don’t become the AI gatekeeper, but the AI enabler.

Chat answers questions.
Cowork finishes tasks.

Chat is a conversation. Cowork is a working session: you describe an outcome, Claude plans it, executes across your files and apps, and reports back when the work is done.

Two modes, two operating models

Regular Chat

  • Single question, single answer
  • No access to files or systems
  • Output lives in the chat window
  • User executes every step
  • Stateless between turns

Claude Cowork

  • Multi-step task, end to end
  • Scoped access to folders and connectors
  • Real files created and edited in place
  • Claude executes, you steer
  • Persistent plan, parallel workstreams

Around Shift Left

AI in modern life is not about personally generating one-off documents or artifacts. It’s about enabling colleagues to collaborate with tools and deliver repeatable capability.

  • Enable colleagues — provide the agent and workflow, not a single generated output.
  • Operationalize intelligence — make insights reusable, reviewable, and owned by the team.
  • Keep the work in the system — use skills, agents, and connectors so the process is repeatable.
  • Ship the agent — deliver the capability, not just the code or a document.

Building Blocks

Start high-level: think knowledge + execution

Knowledge

  • Skills: reusable playbooks Claude can follow
  • CLAUDE.md: local rules for this workspace

Execution

  • Agents: workers that do multi-step tasks
  • MCP Tools: connections to external systems

Skills

A skill is reusable know-how: instructions that teach Claude how to do a specific kind of work

What it does

  • Encodes domain knowledge and best practices
  • Guides how Claude should approach a task
  • Improves consistency for repeated task types

When to use it

  • Inbox triage — define how messages should be categorized
  • PR review workflow — define how comments should be processed
  • Meeting prep — define what material should be collected and summarized

Benefit: reusable expertise without re-explaining the method each time

Agents

An agent is the worker that takes a goal, decides the steps, and executes them end to end

What it does

  • Turns an objective into a concrete plan
  • Executes tasks across files, tools, and systems
  • Coordinates sub-agents when parallel execution helps

When to use it

  • Customer brief — gather sources, analyze them, and draft the output
  • Weekly reporting — collect updates and produce a finished report
  • Code change delivery — inspect, edit, test, and prepare the final summary

Benefit: delegated execution from goal to deliverable

Sub-agents are isolated Claude instances with their own context window and tool access. Intermediate work stays inside the sub-agent and does not clutter the main conversation.

MCP Tools

MCP tools are the connections that let Claude act on external systems

What it does

  • Connects Claude to apps, data, and services
  • Exposes actions like search, read, create, or update
  • Makes the same integration reusable across clients

When to use it

  • Google Drive — read documents and assemble a report
  • GitHub — inspect issues, PRs, and review comments
  • CRM or ticketing — pull customer or case context into a workflow

Benefit: Claude can work with live systems instead of only the chat history

Folder Instructions (CLAUDE.md)

Folder instructions are persistent local rules Claude reads at the start of each session

What it does

  • Sets expectations for how Claude should work here
  • Stores project context, preferences, and constraints
  • Reduces setup effort for every new session

When to use it

  • Team standards — coding rules, review expectations, naming
  • Communication style — tone, audience, brand voice
  • Project context — goals, constraints, preferred workflows

Benefit: Claude starts with the right context instead of being re-briefed every time

Connectors and Plugins

Both extend Claude, but at different levels: connectors add managed access to systems, plugins package full solutions

What they do

  • Connectors — managed integrations for systems like Google Drive, GitHub, or Slack
  • Plugins — installable packs that can combine connectors, skills, commands, and agents
  • Difference — connectors expose systems; plugins package workflows

When to use them

  • Connector — Claude needs access to a live system or data source
  • Plugin — you want a reusable role-based solution for a team or function
  • Examples — connect Salesforce data, or install a sales research pack built on skills and agents

Benefit: connectors provide access, plugins provide packaged capabilities

Connectors are the managed layer on top of MCP and work across Claude clients. Plugins sit above that and bundle multiple capabilities into a more complete product experience.

What are we building

We are building a First Meeting Generator

  1. Assumed Capability Baseline — known / inferred capabilities so we don’t pitch implemented topics.
  2. Strategic Hypothesis — based on the customer’s and competitors’ market positions, we suggest confirmable IT strategies.
  3. Questions to Ask — questions to validate the IT strategic hypothesis.
  4. Strategic Impulses — specific offerings of our company to support the customer with strategies.
  5. PoC Suggestions — clear PoCs with determinable business value based on our strategic impulses.

# Customer Intelligence Pipeline

(...)

## Pipeline Stages

### Phase 1: Company Profiling
1. Check if `output/{domain}/master-data.json` exists (cache check — skip if present)
2. If not cached, spawn **company-profiler** agent for the customer domain and name
3. Verify `output/{domain}/master-data.json` and `output/{domain}/assessment.json` exist

The Pipeline from the Skill

Six phases from company domain to red-team-reviewed meeting pack

  • 1 — Company Profiling. Master data, financials & IT assessment, and recent news for the target company, every fact grounded in a source URL.
  • 2 — Competitive Landscape. Identify 8–12 scale-matched competitors in the same industry and geographies, then profile each one in parallel.
  • 3 — Market Intelligence. Market analysis for the customer plus per-competitor market and head-to-head competition analyses (strengths, weaknesses, strategic implications).
  • 4 — Strategic Synthesis. Business-driven IT strategies across strength amplification, weakness compensation and new-niche differentiation — every strategy tied to an evidence ID, no vendor pitch.
  • 5 — Sales Enablement. Optional service matching against a vendor catalog, then a five-phase meeting prep: capability baseline, draft impulses, IS → TO BE research, POCs, novelty scoring & sharpening.
  • 6 — Report & Red-Team Review. Consolidated Markdown report plus parallel tech- and business-challenger reviews; findings are applied back into the report before it ships.
Each stage caches its output as JSON under output/{domain}/, so re-runs are incremental. Skills: /profile-company, /discover-competitors, /analyze-market, /generate-strategies, /match-services, /prep-meeting, /review-report — or /customer-intel end-to-end.

Claude Cowork Skills

  • customer-intel — Full pipeline orchestrator running phases 1-6: profiling, competitor discovery, market intelligence, strategy synthesis, service matching, and reviewed report output
  • profile-company — Generates company master data, business assessment, and recent news via a company-profiler agent
  • discover-competitors — Finds 8-12 competitors via web search by industry, geography, and revenue scale, then profiles each in parallel
  • analyze-market — Spawns market-researcher agents to produce market and competition analyses from existing data
  • generate-strategies — Derives evidence-based IT strategies (strength amplification, weakness compensation, niche differentiation) using extended thinking
  • match-services — Maps vendor catalog services to IT strategies with value contributions, engagement ideas, and gap analysis
  • prep-meeting — 5-phase sales meeting prep producing strategic impulses and ranked POCs backed by web research
  • review-report — Red-team quality gate spawning tech and business challengers to prioritize issues and apply keep/rewrite/remove actions

Claude Cowork Agents

  • company-profiler — Research agent that gathers master data, business assessment (revenue, employees, IT metrics, digital maturity), and up to 12 recent news items for a given company via web search
  • market-researcher — Analyzes market trends, demand patterns, and competitive positioning from news and assessment data; also produces competition analyses comparing customer vs. competitor
  • tech-challenger — Red-team reviewer that stress-tests technical correctness, architecture feasibility, data dependencies, governance gaps, and novelty of strategic recommendations
  • business-challenger — Red-team reviewer that challenges strategic relevance, customer specificity, stakeholder feasibility, value logic, and commercial differentiation of recommendations

Skill Details - Competition Generator - Part 1


  ---
  name: discover-competitors
  description: Find 8-12 competitors for a company based on industry, market, and revenue scale
  disable-model-invocation: true
  allowed-tools: Agent(company-profiler) Read Write WebSearch
  ---

  # Discover Competitors

  Find competitors for: **$ARGUMENTS**

  Parse: `--domain domain`

  ## Prerequisites
  Read `output/{domain}/master-data.json` and `output/{domain}/assessment.json`. If they don't exist, tell the user to run `/profile-company` first.

  ## Competition Discovery

  Use web search to find competing companies. Definition of "competitor" (must satisfy ALL):
  1. Operates in the same industry segments
  2. Competes in the same geographic markets
  3. Has comparable scale: revenue within ~0.5x to 2x of the customer
  4. Must be an independent company or clearly identified business unit

Skill Details - Competition Generator Part 2


    Process:
  1. Identify the customer's core segments, product lines, and main end-markets (use official sources first)
  2. Identify revenue (most recent year); if private, use multiple estimates and show range
  3. Search for competitors in those segments and markets. Prefer annual reports, investor decks, reputable industry publications, market reports. Avoid low-quality listicles.
  4. Filter to 8-12 best matches
  5. Provide evidence for each: 2-3 citations showing overlap in products/markets and approximate revenue

  Important rules:
  - Always include evidence of direct overlap (specific product lines or business segments)
  - Avoid "same broad industry" matches — overlap must be specific
  - If revenue is missing, provide estimate band with sources and lower confidence

  Write `output/{domain}/competition.json`:
  ```json
  {
    "customerLegalName": "...",
    "customerDomain": "...",
    "competition": [
      { "competitionLegalName": "...", "competitionDomain": "..." }
    ]
  }

  Profile Competitors

  After writing competition.json, spawn company-profiler agents for each competitor — launch in PARALLEL where possible. Each profiles the competitor under output/{competitorDomain}/.
